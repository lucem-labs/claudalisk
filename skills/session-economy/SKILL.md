# Session economy

Every model request sends the whole conversation again, so a long session costs more with every step. These are claudalisk's decisions for keeping sessions small. The app's `AGENTS.md` wins where it lists a deviation (CLA-0028). Before acting on one of these steps, read the ADR.

- [CLA-0073](${CLAUDE_PLUGIN_ROOT}/adr/0073-one-session-per-issue.md) (accepted): one session works on one issue. To hand over, post a handoff note as a comment on the issue and stop; the next session starts from the issue and its latest handoff note.
- [CLA-0074](${CLAUDE_PLUGIN_ROOT}/adr/0074-main-thread-plans-subagent-iterates.md) (accepted): the main thread plans and reviews; once an issue is scoped, the `claudalisk:implementer` subagent runs the build, test and fix loop, commits and pushes only through the verify script, stops on design questions and returns a report of at most 300 words.
- [CLA-0075](${CLAUDE_PLUGIN_ROOT}/adr/0075-compact-at-task-boundaries.md) (accepted): compact after a milestone (tests green, pull request opened, a design question settled), not mid-task, and by about 40% of the context window, never waiting for automatic compaction; when the next step is a new issue, start a new session instead.
- [CLA-0076](${CLAUDE_PLUGIN_ROOT}/adr/0076-one-verify-script-per-cycle.md) (accepted): CI is the only verifier. Check a change with one call to `node scripts/verify.mjs -m "<message>"` (`--backend`, `--frontend`, `--e2e`, `--fail-fast`), which commits, pushes, waits quietly for CI on that commit and prints only the failures from its annotations; failed job logs go to `~/.claudalisk/apps/<app>/verify/`. An app without it copies the plugin's `templates/app/scripts/`.
- [CLA-0077](${CLAUDE_PLUGIN_ROOT}/adr/0077-wait-for-ci-in-one-call.md) (accepted): wait for CI in one call that blocks until the checks finish, never by checking the status again and again; the main thread runs `node scripts/verify.mjs --timeout 60` in the background, the implementer runs it in the foreground, and once the pull request is open the host's pull request monitor, where there is one, is enough.
- [CLA-0078](${CLAUDE_PLUGIN_ROOT}/adr/0078-read-by-range-never-re-read.md) (accepted): find lines with Grep (in the main thread, through the scout), read large files by range with `Read` (not `cat` or `sed` in Bash), and never re-read a file just edited or one unchanged since the last read; briefs to subagents name the lines to change.
- [CLA-0079](${CLAUDE_PLUGIN_ROOT}/adr/0079-subagent-model-and-effort-follow-the-role.md) (accepted): a subagent's model and effort follow its role: implementers and research agents run on Sonnet at medium effort, the code scout on Haiku at low effort, review agents on Sonnet at medium, design agents on Opus or at max effort, and watchers on Haiku; the plugin's agents declare both in frontmatter, and a multi-model review keeps its models but not max effort.
- [CLA-0080](${CLAUDE_PLUGIN_ROOT}/adr/0080-code-discovery-goes-through-the-scout.md) (accepted): the main thread sends every code search and exploratory read to the `claudalisk:scout` agent (Haiku; `Read`, `Grep`, `Glob`, `LSP`; `findReferences` until the count is stable) and reads code itself only by range to edit or check it; the plugin's `scout-gate` hook denies its project-wide `Grep` and `Glob`, whole-file reads over 300 lines and shell searches and reads, and `CLAUDALISK_SCOUT_GATE=off` turns it off.
