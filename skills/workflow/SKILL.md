# Workflow

These are claudalisk's decisions for how work moves from an issue to `main`, and how sessions stay small. The app's `AGENTS.md` wins where it lists a deviation (CLA-0028). Before acting on one of these steps, read the ADR.

- [CLA-0021](${CLAUDE_PLUGIN_ROOT}/adr/0021-issue-driven-work.md) (accepted): every change starts from an issue and becomes one branch in a worktree and one pull request. Open the pull request only when it is ready, and never as a draft. Dependabot pull requests are the one exception.
- [CLA-0073](${CLAUDE_PLUGIN_ROOT}/adr/0073-one-session-per-issue.md) (accepted): one session works on one issue and compacts after milestones by about 40% of the window, never mid-task or into a new issue. To hand over, post a handoff note on the issue and stop.
- [CLA-0074](${CLAUDE_PLUGIN_ROOT}/adr/0074-main-thread-plans-subagent-iterates.md) (accepted): the main thread plans and reviews; the `claudalisk:implementer` subagent runs the build, test and fix loop through the verify script and reports briefly. The implement-and-review workflow runs it with the reviewers, and `work-issue.mjs status` reads an issue's step.
- [CLA-0072](${CLAUDE_PLUGIN_ROOT}/adr/0072-dependabot-updates.md) (accepted): Dependabot opens security updates and weekly grouped version updates for NuGet, npm, actions and Docker. Nothing auto-merges; the owner merges. When CI fails, the agent fixes the Dependabot branch.
- [CLA-0022](${CLAUDE_PLUGIN_ROOT}/adr/0022-bugs-found-become-issues.md) (accepted): bugs found along the way become new `needs-design-review` issues, not inline fixes. An unexplained test failure is rerun once: a pass files a flaky-test issue, and a second failure is investigated as a bug. CI never retries tests.
- [CLA-0023](${CLAUDE_PLUGIN_ROOT}/adr/0023-ready-signoff-and-merge.md) (accepted): open the pull request, never a draft, when CI is green, dev is verified and `/claudalisk:review` is done: Opus reviewer agents, `/code-review`, and a quorum only on high-risk uat data changes. Then review-deploy it to uat; the owner merges.
- [CLA-0076](${CLAUDE_PLUGIN_ROOT}/adr/0076-one-verify-script-per-cycle.md) (accepted): CI is the only verifier: one `node scripts/verify.mjs -m "<message>"` commits, pushes, waits for CI and prints only the failures. Never poll: the main thread runs it in the background, the implementer with `--timeout 4`.
- [CLA-0081](${CLAUDE_PLUGIN_ROOT}/adr/0081-releases-tagged-by-a-workflow.md) (accepted): a pull request that should ship bumps `.claude-plugin/plugin.json`; on `main`, `release.yml` tags `v<version>`, checks every registry item at that tag, creates the release and stages the npm package. Never tag by hand.
- [CLA-0098](${CLAUDE_PLUGIN_ROOT}/adr/0098-artifacts-follow-semantic-versioning.md) (accepted): every claudalisk artifact follows Semantic Versioning 2.0.0. While the major version is 0, a breaking change bumps the minor and everything else the patch. Prereleases are `-alpha.<n>`, `-beta.<n>` or `-rc.<n>`. A released version never changes.
- [CLA-0099](${CLAUDE_PLUGIN_ROOT}/adr/0099-apps-carry-a-version.md) (accepted): an app's version is `version` in the root `package.json`, and every pull request raises it, Dependabot's included. `check-version` enforces it in CI. Deploys and backups record the version, but the commit still identifies a deploy.
- [CLA-0024](${CLAUDE_PLUGIN_ROOT}/adr/0024-owner-merges.md) (accepted): only the owner merges, in GitHub. The agent never merges.
- [CLA-0026](${CLAUDE_PLUGIN_ROOT}/adr/0026-no-real-data-or-secrets-in-git.md) (accepted): env files, backups, dumps and real data never go into commits, pull requests or issues; CI runs gitleaks and a forbidden-file check.
- [CLA-0028](${CLAUDE_PLUGIN_ROOT}/adr/0028-app-agents-md-wins.md) (accepted): the app's `AGENTS.md` holds app facts and lists deviations by ADR id.
- [CLA-0070](${CLAUDE_PLUGIN_ROOT}/adr/0070-testing-layers.md) (accepted): Every behaviour change ships with tests, and each rule is tested at the lowest layer that can see it.
- [CLA-0066](${CLAUDE_PLUGIN_ROOT}/adr/0066-environment-state-outside-the-checkout.md) (accepted): Environment files and backups live outside the checkout, per app and machine.
- [CLA-0078](${CLAUDE_PLUGIN_ROOT}/adr/0078-read-by-range-never-re-read.md) (accepted): find lines with Grep, read large files by range with `Read`, never with `cat` or `sed`, and never re-read a file that is unchanged or just edited.
- [CLA-0079](${CLAUDE_PLUGIN_ROOT}/adr/0079-subagent-model-and-effort-follow-the-role.md) (accepted): a subagent's model and effort follow its role: implementers on Sonnet at medium, reviewers on Opus at medium, design agents on Opus, watchers on Haiku; the plugin's agents declare both in frontmatter.
- [CLA-0088](${CLAUDE_PLUGIN_ROOT}/adr/0088-measure-before-building-token-saving-features.md) (accepted): a token-saving feature is built only after a transcript spike shows the waste, and kept only on the benchmark's verdict. Its tools are claudalisk's own, give deterministic evidence and work on every OS and Claude Code surface.
- [CLA-0094](${CLAUDE_PLUGIN_ROOT}/adr/0094-no-loop-guard.md) (accepted): no loop guard, because repeated failing commands, repeated CI failures and edit churn cost about 0.5% of spend; a later guard needs a new transcript spike showing more than 2%.
- [CLA-0095](${CLAUDE_PLUGIN_ROOT}/adr/0095-no-tool-output-compression.md) (accepted): no hook rewrites or filters tool output, because build, test, lint, CI and git output is about 4% of context and file reads and search are 31%; `verify.mjs` stays the one compaction for CI output.
- [CLA-0096](${CLAUDE_PLUGIN_ROOT}/adr/0096-design-work-in-a-design-repository.md) (accepted): design work lives in the owner's design repository and design sessions start there; apps set `"enableArtifact": false` in `.claude/settings.json`. An existing app moves any design folder to the design repository, then adds the setting.
- [CLA-0097](${CLAUDE_PLUGIN_ROOT}/adr/0097-plugin-enabled-per-app.md) (accepted): the plugin is off in user settings, and each app's committed `.claude/settings.json` sets `"enabledPlugins": { "claudalisk@claudalisk": true }`, so every checkout and worktree of the app loads it and other folders do not. An existing app adds the setting.
