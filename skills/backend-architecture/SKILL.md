# Backend architecture

These are claudalisk's decisions for backend code. The app's `AGENTS.md` wins where it lists a deviation (CLA-0028). Before changing code that one of these decisions covers, read the ADR.

- [CLA-0001](${CLAUDE_PLUGIN_ROOT}/adr/0001-modular-monolith.md) (accepted): one deployable app; its one Host, `<Root>.Api`, composes the modules and holds only business-neutral endpoints. Each module is a bounded context named by a singular noun, and a cross-module call may be in-process, queued or remote.
- [CLA-0002](${CLAUDE_PLUGIN_ROOT}/adr/0002-interfaces-projects.md) (accepted): modules reference only other modules' `*.Interfaces` projects. Only the Host and tests reference implementations; shared infrastructure comes from claudalisk packages.
- [CLA-0003](${CLAUDE_PLUGIN_ROOT}/adr/0003-lean-interfaces-projects.md) (accepted): interfaces pass messages, which are logic-free POCOs owned by one Interfaces project. Never share them across Interfaces projects, never call them models. An Interfaces project references nothing, and callers name the result type when they send.
- [CLA-0004](${CLAUDE_PLUGIN_ROOT}/adr/0004-module-registration.md) (accepted): modules register themselves idempotently, declare dependencies by marker classes, and add their controllers as application parts.
- [CLA-0005](${CLAUDE_PLUGIN_ROOT}/adr/0005-modules-expose-thin-controllers.md) (accepted): a module exposes its own thin controllers, which do HTTP only. DTOs live in their feature or the module's `Shared/`, may use MVC but never EF Core, and are never shared between modules. The Host holds no business logic.
- [CLA-0006](${CLAUDE_PLUGIN_ROOT}/adr/0006-architecture-tests-by-convention.md) (accepted): architecture tests find modules by naming convention, not hand-kept lists. Every rule asserts that its scan found something and has a guard test that shows it flags a bad example. Each ADR's "Enforced by" line names its rules.
- [CLA-0007](${CLAUDE_PLUGIN_ROOT}/adr/0007-persistence-owns-ef-core.md) (accepted): Each module owns its schema; cross-module work uses a unit of work or the queue.
- [CLA-0041](${CLAUDE_PLUGIN_ROOT}/adr/0041-module-api-is-a-bounded-context.md) (accepted): a module's API is its bounded context. Names come from its ubiquitous language, a resource belongs to one module, and the API changes by addition without versions.
- [CLA-0042](${CLAUDE_PLUGIN_ROOT}/adr/0042-resources-are-aggregates.md) (accepted): aggregate roots are resources with one URL and child entities live under their root. Plain edits use PUT or PATCH, and read models are their own GET resources.
- [CLA-0043](${CLAUDE_PLUGIN_ROOT}/adr/0043-state-changes-are-domain-commands.md) (accepted): state changes are POSTs to a sub-resource named after the domain command, such as `/cancel`. Never write status fields directly.
- [CLA-0044](${CLAUDE_PLUGIN_ROOT}/adr/0044-hypermedia-links-and-actions.md) (accepted): representations carry HAL-style `_links` and the `_actions` the aggregate allows now, and the UI shows only those actions. A `204` carries neither.
- [CLA-0045](${CLAUDE_PLUGIN_ROOT}/adr/0045-http-semantics-and-problem-details.md) (accepted): standard status codes, RFC 9457 Problem Details with a `type` per domain error, and ETag with If-Match on writes.
- [CLA-0046](${CLAUDE_PLUGIN_ROOT}/adr/0046-openapi-document.md) (accepted): the OpenAPI document groups endpoints by module through a registration convention. Schema names are unique, and building the document fails on a collision. Frontend API types are generated from it and checked in CI.
- [CLA-0047](${CLAUDE_PLUGIN_ROOT}/adr/0047-modules-organized-by-feature.md) (accepted): one `Features/<UseCase>/` folder per command, query or CRUD resource, holding its controller, DTOs, request, handler and mapping; tests mirror features. A response DTO that several features return goes in `Shared/`, grouped by resource.
- [CLA-0048](${CLAUDE_PLUGIN_ROOT}/adr/0048-aggregates-in-a-domain-project.md) (accepted): aggregates and IO-free algorithms live in a plain-C# `<Root>.Modules.<Name>.Domain` project, and Persistence stores map EF Core entities to and from them. A pure function of state decides the allowed commands and `_actions`.
- [CLA-0049](${CLAUDE_PLUGIN_ROOT}/adr/0049-features-go-through-the-dispatcher.md) (accepted): every feature sends its commands and queries through the dispatcher, with one handler each. Logging, validation, the retry of a lost race and the unit of work are pipeline steps.
- [CLA-0050](${CLAUDE_PLUGIN_ROOT}/adr/0050-module-dependencies-go-down-feature-first.md) (accepted): features never reference each other; dependencies go down to the module's `Shared/` and Domain project. Domain rules start in the aggregate; other code starts in its feature and moves to `Shared/` on its second use.
- [CLA-0052](${CLAUDE_PLUGIN_ROOT}/adr/0052-cqrs-naming.md) (accepted): `<Verb><Noun>Command`, `Get`/`List`/`Search` + `Query`, `<Message>Handler`, past-tense events with no suffix, `<Aggregate>Entity` for the aggregate root's EF Core entity, `I<Aggregate>Store` and `I<Aggregate>ReadStore`, and identifiers in US English.
- [CLA-0057](${CLAUDE_PLUGIN_ROOT}/adr/0057-validation-fluentvalidation-and-aggregates.md) (accepted): FluentValidation `<Message>Validator` classes check input shape in the pipeline and return `400`; domain rules live in the aggregate and return `409`. A limit that protects one endpoint is set on that endpoint.
- [CLA-0058](${CLAUDE_PLUGIN_ROOT}/adr/0058-queued-work-jobs-library.md) (accepted): a job is a command the jobs library runs later, for repeated third-party calls and work that can outlast a request. It stores its normalised plan, joins the caller's unit of work and retries all but domain and validation failures.
- [CLA-0059](${CLAUDE_PLUGIN_ROOT}/adr/0059-batch-jobs.md) (accepted): work that calls a third-party API more than once or can outlast a request implements the batch-job type; the library commits each batch with its checkpoint in its own unit of work, and retries resume from the checkpoint.
- [CLA-0060](${CLAUDE_PLUGIN_ROOT}/adr/0060-jobs-router-and-job-resource.md) (accepted): an endpoint that starts a job returns `202` with `/api/jobs/{module}/{id}`, and the job's `result` link always resolves. A read model never computed answers `404` with a `<resource>-not-computed` problem, and its parent offers the start action.
- [CLA-0061](${CLAUDE_PLUGIN_ROOT}/adr/0061-scheduler-module.md) (accepted): recurring work comes from the scheduler module, which sends a command to a module through the dispatcher once per fire time. Schedules live in the env file, and an owner-configured schedule counts as an owner trigger.
- [CLA-0062](${CLAUDE_PLUGIN_ROOT}/adr/0062-claudalisk-nuget-packages.md) (accepted): business-neutral infrastructure ships as claudalisk NuGet packages that apps pin; the packages repository decides their names.
- [CLA-0063](${CLAUDE_PLUGIN_ROOT}/adr/0063-domain-exceptions-and-one-problem-handler.md) (accepted): aggregates and handlers throw `DomainException` subclasses with a slug, title and kind. One handler from the claudalisk web package maps them, validation, `If-Match` and lost races to Problem Details; an outage throws `DependencyUnavailableException` (503).
- [CLA-0064](${CLAUDE_PLUGIN_ROOT}/adr/0064-repository-and-test-layout.md) (accepted): `backend/`, `frontend/` (with `src/` and `e2e/`) and `scripts/`; one `<Root>.Modules.<Name>.Tests` project per module with folders that mirror features, plus `<Root>.ArchitectureTests`.
- [CLA-0067](${CLAUDE_PLUGIN_ROOT}/adr/0067-module-contracts-are-messages-only.md) (accepted): Interfaces projects hold only messages and the module marker; modules call each other only through the dispatcher; a `JobReference` result means the work runs later, and the Host decides whether a module is local or remote.
- [CLA-0068](${CLAUDE_PLUGIN_ROOT}/adr/0068-events-fan-out-as-jobs.md) (accepted): aggregates record domain events; publishing writes one job per subscriber in the unit of work, and handlers run after the commit, retry, and record the event ids they handled. Integration events carry facts and live in the publisher's Interfaces project.
- [CLA-0069](${CLAUDE_PLUGIN_ROOT}/adr/0069-hand-written-mapping.md) (accepted): mapping is internal extension methods in the consuming project; never AutoMapper, Mapster, Mapperly or mapper interfaces.
